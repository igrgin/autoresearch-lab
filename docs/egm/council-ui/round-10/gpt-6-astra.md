- **Functionality: 9/10.** Creating a project has one clear required field and a strong primary action. Search, recency sorting, explicit Open buttons, and path inspection support finding and reopening work. The reopened state clearly identifies the current project in both panels and preserves access to New project. These scores reflect visible interaction design, not runtime verification.
- **Appearance: 9/10.** The restrained palette, consistent typography, generous spacing, and persistent navigation feel cohesive. Selection and primary actions are easy to distinguish. Technical location details and dense row metadata introduce some minor visual friction.

Specific issues, ordered by importance:

1. **Location details occupy a disproportionate amount of the side panels.** Folder names, multiline parent paths, and additional path controls compete with the simple create/reopen workflow. In the reopened screenshot, the panel extends beyond the viewport. Compact the location section and use its existing disclosure to expose expanded details while retaining clear access to path inspection.

2. **Saved-project metadata feels crowded horizontally.** Folder identifiers, underlined path links, and precise timestamps share a narrow band beneath each title. Give recency its own consistent secondary line and group the folder identifier with its path action. Preserve the useful second-level precision.

3. **Path-action wording varies unnecessarily.** “Show full path” and “Show full project path” describe the same kind of inspection with different specificity. Standardize the label, and visually associate each action with the folder information it expands.
