## Runtime boundaries

- [Electron host](../../../src/security/electron-vault.ts) owns asynchronous `safeStorage`, restricted to macOS, and ciphertext under the installation's `userData/private-credentials/credentials.vault`. The vault is outside project databases; directories are owner-only, files are mode 0600, writes use fsync and atomic replacement, and reads refuse symlinks. There is no plaintext fallback. Main does not start crashReporter, heap/network dumps or diagnostic uploads.
- The separate Credential settings window has a sandboxed preload with entry, safe metadata, replacement and app revocation only. Every IPC handler checks the actual window and main frame. The ordinary renderer's existing bridge remains read-only shell status. Password input clears after acknowledgment; no stored value is returned. The service rejects secret-bearing labels.
- [Credential service](../../../src/security/credentials.ts) supplies bootstrap-created adapter handles bound to component, category, account, purpose, and exact project/run/action/operation scope. Handles take no model-provided component, URL, account or credential override. The trusted handler closure binds the intended resource/operation. Renderer/model code cannot construct handles. Unknown references, wrong category/account/purpose/scope and revoked values fail before dispatch. Revocation aborts authenticated operations; adapters must connect that signal to worker termination and scope reconciliation.
- Persistent categories are Runpod, Vast, OpenAI, Anthropic, SSH passphrase, model download, and optional application control capability. Provider-issued Vast sessions have a separate operation-scoped memory-only method. Passwords, OTP, recovery codes, SSH private-key files and signing sockets have no vault import API. Existing SSH files/agents remain with the transport; no automatic copying or key registration occurs. Model tokens are for trusted fetch operations, not arbitrary downloader code.
- Replacement creates a new reference with the same account/category, retires old authentication authority, and keeps its value only in encrypted remediation matching state. Issuer-side revocation and verification remain explicit trusted actions. `finishRemediation` removes retired matching material after completed rescan/containment; callers must not invoke it merely because a replacement was saved.

## Admission, reuse and failure

[SafeRecording](../../../src/security/recording.ts) admits only validated envelopes and sanitized JSON-compatible detail. The small private file port supplies executable persistence for this shared boundary without introducing a second project database writer. History/remote integrations must use admitted values before SQLite/WAL, remote spools, indexes, UI/notifications, exports, telemetry or models. They must not bypass admission by serializing vendor objects first.

Supported capture paths: prompts, assistant prose, command text, argv, cwd, stdout, stderr, tool arguments/results, vendor errors, stack text, file names/content/diffs, Git messages, text attachments, summaries, metric labels, model metadata, application logs and allowlisted provider projections. Authentication RPCs, headers, credential files, raw environments, provider/SDK objects and native transcripts are excluded. Binary/opaque attachments are withheld.

The versioned sanitizer handles registered current/retired values, standard JSON string escaping, fully Unicode-escaped strings, uppercase/lowercase percent encoding, double URL encoding, designated credential fields, URL userinfo/secret queries, common token forms and private-key blocks. JSON streams are decoded and parsed only on complete frames, so arbitrary legal JSON escapes normalize before scanning. Text streams support the explicitly registered representations; arbitrary transformations are not a universal secret detector. Isolation and restricted sources remain necessary.

Streaming holds a complete bounded frame before any disclosure, including UTF-8/escape boundaries. It drains/discards excess bytes without emitting a prefix. The 4 MiB admission frame bound, 32-level depth bound and node bound are defensive parser bounds; they do not replace or alter #86's 64 KiB body, bucket/run limits or capture queue policy. #91 applies retention cuts **after** sanitation. Malformed/incomplete/opaque/oversized bodies retain safe identity/status/policy/omission metadata only. Semantic task/code/validation/constraint/acceptance records require exact schemas; invalid required content cannot become agent context or a successful broker return.

`bindRecordedOperation` admits a successful trusted result before returning it to model-facing code. `requireCredentialFreeCommand` rejects credential-bearing command input before execution. The fixed-origin provider read helper supports GET only, rejects redirects and lifecycle routes, and returns raw responses only to trusted projection code. Child environment construction uses an explicit allowlist, with only Claude's own inference credential added for its trusted worker. It does not establish OS isolation.

Every read projection rechecks current matching policy and quarantine. A newly discovered secret in an older stored body is an **exposure**, revokes known authority and fences the run. Agent projection additionally requires an authorized project/run scope and exact task/code/validation/constraint/acceptance shapes; test assessments, raw history, summaries, unknown fields and other runs are excluded. #66 must authorize source semantics and construct later-run context; placing a test score inside an otherwise authorized prose field cannot be solved by a secret matcher.

Broken filtering or storage fences new affected work. A separate fixed-schema control receipt remains available even when the general sanitizer is broken; it has no free-text fallback. Post-dispatch failures report unknown effects and require reconciliation rather than replay. These services do not decide experiment outcomes, alter acceptance, release reservations, or invoke provider lifecycle APIs.

## Incidents and recovery

Incidents contain identities, destinations, prevented/exposed/unknown reach, policy, safe reason and incomplete remediation coverage, never values/excerpts/hashes. Propagation fences apply synchronously before IO. Durable state withholds identified records and all projections of the affected run while containment is open; session IDs remain permanently retired. Quarantine occurs in place, without a raw evidence archive. Corrections receive new IDs and a `supersedes` reference; the original becomes a safe tombstone.

Recovery requires trusted attestations of replacement access, boundary verification, reconciled effects, completed containment, explicit Resume and a fresh session. These are integration gates, not claims that the service itself can revoke a provider key, inspect remote native history, prove process termination or retract a model's context. Unknown/inaccessible remote copies, backups, exports, native caches and filesystem snapshots keep containment incomplete. Logical replacement is not forensic erasure.
