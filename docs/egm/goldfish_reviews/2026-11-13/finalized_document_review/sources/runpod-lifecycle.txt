Stop a Pod
Stopping a Pod releases the GPU and preserves data in
/workspace
(volume disk). Container disk data is cleared.
You’ll still be charged for
volume disk storage
while stopped. Terminate the Pod if you don’t need to retain your environment.
When using a
network volume
, your
/workspace
data is preserved whether you stop or terminate the Pod.
Web
CLI
REST API
Open the
Pods page
and expand your Pod.
Click the
Stop
button (square icon) and confirm.
runpodctl
pod
stop
$RUNPOD_POD_ID
Schedule a stop
(e.g., after 2 hours):
sleep
2h
;
runpodctl
pod
stop
$RUNPOD_POD_ID &
curl
--request
POST
\
--url
"https://api.runpod.io/v2/pods/
$RUNPOD_POD_ID
/action"
\
--header
"Authorization: Bearer
$RUNPOD_API_KEY
"
\
--header
'Content-Type: application/json'
\
--data
'{"action":"stop"}'
​
Start a Pod
Resume a stopped Pod. Note: You may be allocated
zero GPUs
if capacity has changed.
Web
CLI
REST API
Open the
Pods page
and expand your Pod.
Click the
Start
button (play icon).
runpodctl
pod
start
$RUNPOD_POD_ID
curl
--request
POST
\
--url
"https://api.runpod.io/v2/pods/
$RUNPOD_POD_ID
/action"
\
--header
"Authorization: Bearer
$RUNPOD_API_KEY
"
\
--header
'Content-Type: application/json'
\
--data
'{"action":"start"}'
Unlike the console, the REST
start
action does not offer a zero-GPU start. If the GPUs on the Pod’s host machine are no longer free, the request fails with
400
and a message saying there are not enough free GPUs on the host.
​
Restart a Pod
Restarting reboots a running Pod’s container on the same machine. The Pod keeps its GPU, so it’s a safe way to reload a process, such as one running as PID 1. Unlike stopping and starting, restarting can’t leave you with
zero GPUs
.
Web
CLI
REST API
Open the
Pods page
.
Open the Pod’s three-dot menu and click
Restart Pod
.
runpodctl
pod
restart
$RUNPOD_POD_ID
curl
--request
POST
\
--url
"https://api.runpod.io/v2/pods/
$RUNPOD_POD_ID
/action"
\
--header
'Authorization: Bearer RUNPOD_API_KEY'
\
--header
'Content-Type: application/json'
\
--data
'{"action": "restart"}'

Update a Pod
Modify an existing Pod’s configuration, such as storage size, image, ports, or environment variables.
Editing a running Pod resets it completely, erasing all data not stored in
/workspace
or a network volume.
Web
REST API
Open the
Pods page
.
Click the three-dot menu next to the Pod you want to update.
Click
Edit Pod
and modify your configuration.
Click
Save
to apply changes.
curl
--request
PATCH
\
--url
"https://api.runpod.io/v2/pods/
$RUNPOD_POD_ID
"
\
--header
"Authorization: Bearer
$RUNPOD_API_KEY
"
\
--header
'Content-Type: application/json'
\
--data
'{
"disk": 100,
"mounts": {"persistent": {"size": 200, "path": "/workspace"}}
}'
See the
Update a Pod reference
for all editable fields.

network volume
. Export important data first.

CLI
REST API

Stop the Pod if running, then click

(trash icon) and confirm.

"https://api.runpod.io/v2/pods/
$RUNPOD_POD_ID
"
\
--header
"Authorization: Bearer
$RUNPOD_API_KEY
"

View logs
Pods provide two log types:
Container logs
: Application output (stdout)
System logs
: Pod lifecycle events (startup, shutdown, errors)
Access logs from the
Pods page
by expanding your Pod and clicking
Logs
.
